@axiom.internal

Dev accounts are the isolated @axiom.internal class on the dev-AXC pool — separate money from the public supply. They receive through TOT→FATMAMA, which exists only on a development fleet, so a dev wallet cannot transact against a production validator.

The wallet key signs your transactions and is never stored. Your wallet is encrypted at rest with this key (PBKDF2 + XSalsa20-Poly1305) before it touches this browser's storage — so the key is also what decrypts it. If you lose or mistype it, the wallet cannot be recovered.

Bring a wallet over from a validator, the desktop wallet, or another browser. Accepted: a validator's wallet.axiom (copy the file straight across — this is how a wallet comes back after a stake claim), or an encrypted backup (Mac: Wallets → Export → wallet.axpw). Choose the file here and reuse the Name + Wallet key fields above — the key must be the one the wallet uses. It is re-encrypted at rest in this browser under that key (dev passcode + confirm-key don't apply to import).

Claim a validator stake

        

          This is a special feature. It claims a validator stake into
          this wallet from a subsidy pool. It does not set up, contact or
          register a validator — you claim here, then copy this wallet to your
          validator machine.
        


        

          This wallet is stake-locked.
          

        


        

          

            Bootstrap — claims 505 AXC
            
Community. Stake floor 500 AXC; the extra 5 covers fees.

          

          

            Foundation — claims 6,060 AXC
            
Foundation seat. Same stake floor as everyone, 500 AXC; the claim lands at least 6,000 AXC after fees.

          

        


        

          Read this before you claim.
          
    
            
  • The stake arrives in this wallet and is then locked. You keep it; you cannot move it.
    • 
            
  • While locked the wallet can still receive, but cannot send or redeem.
    • 
            
  • The lock ends by time only. There is no unlock step and nobody can release it early — after the deadline your next send simply works.
    • 
            
  • A claim is not reversible. This is not the ordinary airdrop.
    • 
          

        


        

          The claim itself runs on your validator, not here.
          

            A stake claim requires a validator certificate, and Core refuses one
            without it (ValidatorJoinNoProvisionalVbc) — that gate is
            what stops an ordinary wallet drawing from the pools.
            


            The reason the claim does not run here is delivery, not permission:
            the claim's cheque is mailed to your wallet, and a browser cannot
            read a mailbox. The claim would be sent and the money never collected.
            


            So the order is: export this wallet → copy it to the validator
            machine → claim there. The stake then lives in this wallet, locked,
            exactly as described above. To bring it back afterwards: log out,
            then Import a wallet on the login screen and choose the
            validator's wallet.axiom — the stake and its lock come with it.
          

        

        

      


      

        
Move this wallet to your validator

        

          The stake lives in this wallet, so the validator needs this wallet file.
          Export it, copy it to the validator machine, and keep the passphrase —
          the file is encrypted and useless without it.
        

        
        

          Anyone holding this file and its passphrase controls the stake. Treat it like the key it is.
        

      


      
      

        
Register a validator certificate

        

          An issued certificate is not usable until Nabla stamps it. Nabla checks
          this wallet — the stake wallet the certificate names — against its own
          records (the wallet exists, holds the stake floor, sits at its confirmed head)
          and either stamps the certificate or refuses. Each certificate can be
          registered once.
        

        
        
        

          Choose the validator's config/vbc-bundle.cbor. On success the stamped
          file downloads — copy it back over config/vbc-bundle.cbor on the validator.
